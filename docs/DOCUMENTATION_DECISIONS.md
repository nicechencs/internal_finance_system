# 文档整理决策记录

状态：Active
适用对象：开发 / 运维 / AI
事实源级别：Primary
最后核对日期：2026-08-16

## 决策

### 1. 以代码现状为准

原因：
- 现有文档之间存在明显冲突。
- 认证、API 路由、响应结构、默认账号、部署流程都已经发生演进。
- 如果继续以旧文档互相引用为准，会持续传播错误信息。

执行结果：
- 认证与 API 事实以 `backend/FinanceApp.Api/` 和 `frontend/src/` 中的实现为准。
- 部署事实以 workflow、根目录 Compose 和 `scripts/*.sh` 为准。

### 2. 建立单一事实源

原因：
- 同一件事被写成多套版本，是当前最主要的维护成本来源。

执行结果：
- `docs/` 下只保留当前有效的主文档。
- 历史报告、计划、Prompt 模板统一迁入 `docs/90_Archive/`。

### 3. SQL 与说明文档分离

原因：
- `docs/02_Database/` 同时放说明、Schema、补丁 SQL、种子脚本，语义混乱。
- 开发与部署脚本需要稳定的 SQL 路径。

执行结果：
- `database/schema/` 存放可读 Schema。
- `database/manual_sql/legacy/` 存放历史手工补丁。
- `database/seed/` 存放种子脚本。

### 4. 旧文档优先归档，不直接删除

原因：
- 中文业务描述、历史决策和修复背景仍有追溯价值。
- 直接删除容易丢失你强调过的重要信息。

执行结果：
- 旧文档优先整体移动到归档目录。
- 新文档以精简总结和链接形式接管主阅读路径。

### 5. 已知问题需要按代码复核

原因：
- `known_issues` 中部分条目已经有代码或前端入口支持。

执行结果：
- 保留仍然有效的问题。
- 将“已实现但非自动化”的条目标记为“限制仍在，但已有人工 / 半自动工具”。

### 6. 记录不确定项

原因：
- 有些问题需要 UI 复测或业务确认，不能靠静态阅读文档直接下结论。

执行结果：
- 原记录于 `docs/DOCUMENTATION_OPEN_QUESTIONS.md`，2026-04-09 全部项已闭环或转入 backlog/known_issues，并归档为 `docs/90_Archive/documentation_open_questions_closed_2026-04-09.md`。
- 后续不确定项直接在 backlog 或 known_issues 中跟踪。

### 7. 根入口文档只保留导航和高频事实

原因：
- `README.md`、`CLAUDE.md`、局部 README 最容易在多次迭代中与主文档脱节。
- 把完整说明重复写在多个入口文件里，会再次产生“同一事实多套版本”。

执行结果：
- 根入口文档改为“项目概览 + 快速开始 + 文档入口”。
- 详细产品、API、运维说明统一回收到 `docs/` 主目录。

### 8. 核心中文文档统一按 UTF-8 维护

原因：
- 仓库内存在中文文档与脚本的编码混用风险，容易在 Windows 终端或 AI 工具读取时出现乱码。
- 文档整理后如果继续保留混合编码，后续合并和校对成本会持续上升。

执行结果：
- 本轮重写的根入口文档、脚本说明和协作文档统一按 UTF-8 维护。
- 后续如发现旧文件仍使用历史编码，应在整理时一并标准化。

### 9. 面向公开仓库的产品命名

原因：
- 开源前需要去掉仅对单一组织有意义的内部称呼，以及会暴露私人镜像账号的默认值。
- 不另起一套全新品牌，只把用户可见名称收束为对产品本身的中性描述。

执行结果：
- 用户可见中文名称统一为「财务管理系统」，英文副标题为 `Finance Management System`。
- 代码标识统一为 `FinanceApp.*`，数据库/容器/镜像使用 `finance*` / `finance-api` / `finance-web`。
- 生产镜像默认所有者改为占位符 `your-github-username`，由部署方自行填写。
- 开发演示账号为 `admin / DemoOnly_ChangeMe!`，生产环境拒绝使用已公开的演示密码作为引导管理员密码。

### 10. 开源第二遍：归档快照与测试部署触发

原因：
- 第一遍把 `docs/90_Archive/` 留作历史快照，但公开后归档同样会被检索；其中仍含旧工程名、旧部署路径和已废弃的 PaaS/镜像仓库表述。
- 测试环境 GitHub Actions 在推送 `dev` 时自动 SSH，公开仓库不适合作为默认行为。

执行结果：
- 归档文档中的 `InternalFinance` / `internal-finance` / `internal_finance` 已机械替换为现行公开标识；私人用户名、演示密码和真实样本在归档中本就没有残留。
- `deploy-testing.yml` 改为仅 `workflow_dispatch`。
